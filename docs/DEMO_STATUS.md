# Investor demo status

## Demo path

1. Open `/stocks`; browse/search the configured universe. The `VNM/SAB/MCM/SBT` preset is a demo convenience, not a system limit. The current generated workbook contains four complete records; other tickers mentioned in alternate workbook notes have not been imported as complete profiles.
2. Open a company profile from the directory and run its OSINT scan. With `NEXT_PUBLIC_USE_MOCK=false`, the same-origin Next.js route calls FastAPI and LangGraph runs `discover → graph_enrichment → extract → classify → validate`. Discovery runs four Firecrawl penalty queries per ticker (tax, environment, securities, administrative) with article scraping, a bounded Jina Reader fallback (max 3 results), and a read-only Neo4j lookup. Results without readable text are not sent to the model. If FastAPI is unreachable, the Next.js route returns workbook events as `DEMO DATA`; there is no second search implementation in Next.js. LangChain/Groq or Gemini returns schema-checked proposals; evidence quotes must match extracted article text before severity/preview penalty is accepted. If live search returns no articles, the model is skipped and any workbook fallback is marked `DEMO DATA`. Findings remain unverified and review actions only affect the current browser session; no approved-event store or audit log exists yet.
3. Select symbols in the directory and open Portfolio Optimizer. The selected tickers carry over. Current weight scenarios only cover the four demo tickers; additions require matching scenario/solver inputs and feasible constraints. Sliders select the nearest existing scenario from the workbook; they do not run a fresh covariance-based optimizer.
4. Open `/private`, add up to ten documents, and process them sequentially. PDF text extraction/OCR and Rules baseline run in the browser. With a separate consent checkbox, extracted text can run through the LangGraph/LangChain Document Agent; page/quote/value grounding is required before AI values enter Z′. Results can be printed.

## Deep-demo API foundation

- A separate FastAPI service under `backend/` serves a searchable, cursor-paginated universe from generated workbook JSON and returns data-version/provenance/status metadata.
- FastAPI has been reorganized into a composition root with versioned API routers, domain contracts, workbook and universe repositories, service adapters, and LangGraph agents; existing API paths are preserved.
- New tickers can be registered with a source reference. They are stored in local SQLite as `pending_data` and list required fields still missing; registration does not fabricate metrics.
- If a data maintainer adds a ticker to the workbook `Companies` sheet before filling every required Market/Financials/ESG input, the build pipeline exports it to `universe_pending.json`; FastAPI serves it as `pending_data` instead of failing the whole build or inventing metrics.
- Implemented routes include `/health`, Neo4j readiness, paginated company/universe reads, company Z-score/ESG/OSINT and methodology/scenario reads, portfolio workbook-scenario read, ticker registration, assessment, `POST /api/v1/osint/scans`, and opt-in `POST /api/v1/private/extract`.
- `.env.local` is configured with `NEXT_PUBLIC_USE_MOCK=false` and the local FastAPI URL. The original company lookup page remains available at `/company/VNM`; public data reads go through FastAPI. PDF processing stays in-browser. Portfolio still selects workbook scenarios.
- OSINT was manually exercised through `POST /api/osint/scan` in Next.js: response `200`, LangGraph `discover → graph_enrichment → extract → classify → validate`, and connected Neo4j adapter. Live-provider run returned 9 candidates and Groq structured proposals; proposal and exact-quote counts vary. Provider requests can return no articles, in which case the model is correctly skipped. The database has no nodes, so graph matching returns empty. Candidates remain for review; these are point-in-time checks, not a reliability guarantee.
- `/stocks` now submits new tickers through a same-origin Next.js API proxy to the FastAPI registry and shows registered symbols as `pending_data`; pending symbols cannot be selected into the optimizer or opened as scored profiles until source data is imported and validated.
- Run instructions and configuration are in [demo runbook](DEMO_RUNBOOK.md), [backend README](../backend/README.md), and [.env.example](../.env.example). Generate JSON first with `npm run data`, then run FastAPI and Next.js.

## Accurate demo claims

- Financial metrics CAPM, price-period realized return, Altman X1–X5/Z/zone, and RFin base are recalculated from workbook inputs by `scripts/build-data.mjs` and reconciled to the saved workbook formulas. The dataset itself remains historical workbook data (BCTC 2024 / price inputs 2025), not a live market feed.
- ESGi and portfolio allocations still come from workbook inputs. Portfolio sliders select the nearest precomputed scenario; there is no fresh covariance-based solver run.
- Firecrawl is the only discovery source; Jina Reader may extract public article text Firecrawl could not scrape. The LangGraph workflow and LangChain model call are real when dependencies and keys are configured. The LLM classifies only returned title/excerpt and proposes evidence; it does not prove an allegation. Candidate events must not be described as confirmed violations.
- Neo4j Aura is connected through the backend's read-only Python adapter. The graph is empty until an operator deliberately runs the write-gated workbook demo seed. Aura hosted MCP is separately configured for an MCP-compatible IDE with browser OAuth; the app backend does not use Aura API client secrets.
- Synchronous OSINT is capped at four tickers per request (16 Firecrawl queries). Each ticker costs roughly 4 × (2 + `OSINT_FIRECRAWL_LIMIT`) Firecrawl credits per scan.
- A local “Duyệt” action previews a POSINT impact; it does not write to the company profile or persist an audit trail.
- PDF text/OCR and rule parser run in the browser. With separate user opt-in, extracted text is sent to the configured LLM; a LangGraph extraction/quote-validation workflow maps fields without requiring one exact layout. Values without page/quote evidence are rejected and rule-parser values remain the comparison baseline. The original PDF is not sent. There is no RAG, cross-document conflict resolution, persistent field approval workflow, or persistence of private findings.
- The document request is bounded and selects finance-relevant lines to reduce provider context errors. A provider may still reject requests or hit quota; in that case results remain on Rules baseline and UI reports the agent unavailable.
- The browser drops its references to uploaded files after processing. This does not establish deletion from browser memory, logs, caches, or external infrastructure.
- Portfolio weights come from existing workbook scenarios, not a new QUBO/QAOA run. No quantum hardware or QAOA result is claimed.
- Adding a ticker to the universe requires complete sourced input data; an arbitrary ticker string does not create financial/ESG metrics.

Live OSINT requires `FIRECRAWL_API_KEY`; without it the scan returns workbook events labelled `DEMO DATA`. For LLM proposals set `AI_PROVIDER=groq|gemini` (or `OSINT_AI_PROVIDER` for OSINT only) and the matching server-side model key. `JINA_API_KEY` is optional. Copy missing variable names from `.env.example`, preserve existing `.env.local` keys, then restart Next.js. Keep keys server-side; do not use `NEXT_PUBLIC_` names for them. Public article excerpts will be sent to the configured LLM provider; do not use this flow for confidential/private document text.
