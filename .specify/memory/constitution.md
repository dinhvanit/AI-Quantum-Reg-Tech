# QuantumRegTech Constitution

## 1. Evidence before conclusions

Every public finding, extracted private metric, and generated report statement MUST retain its source, retrieval/extraction time, and evidence reference. An article mentioning a company is a signal, not proof of a violation. Missing or conflicting values remain missing or visibly disputed; they MUST NOT be fabricated or silently reconciled.

## 2. Deterministic financial calculations

Financial formulas, units, thresholds, and methodology versions MUST live in typed deterministic code/configuration. LLMs may extract, classify, or explain cited evidence, but MUST NOT calculate authoritative ratios, scores, weights, penalties, or portfolio constraints.

## 3. Human approval for consequential updates

Unverified OSINT and PDF extractions MUST remain proposals until a reviewer approves them. POSINT changes MUST be attributable to approved findings and an audit record. AI-generated summaries MUST be distinguishable from verified facts and calculated values.

## 4. Privacy by design

Private PDFs MUST be processed locally by default. Any transfer of document text to an external model requires explicit user notice and consent. Secrets MUST remain server-side. Do not claim zero retention unless storage, logs, traces, caches, and backups support that claim.

## 5. Bounded, auditable automation

Agent workflows MUST be explicit state graphs with allowlisted tools, validated structured outputs, bounded retries, and human approval gates. Untrusted web/PDF content MUST never be treated as instructions or allowed to authorize tools.

## 6. Honest model and data labels

Every view/report MUST distinguish demo data from live data, source dates, public from private evidence, model estimates from reported values, and classical results from quantum results. No quantum advantage or QAOA label without a real, reproducible implementation.

## 7. Incremental architecture

Keep the existing Next.js app as the user-facing product. Extract Python services only where LangGraph, document processing, or portfolio optimization materially benefits. External integrations MUST sit behind adapters so providers can be changed without changing domain logic.

## 8. Acceptance

Feature specifications define observable user behavior and acceptance criteria before implementation. Formula changes require a methodology/version note and data-owner decision. Demo data must be deterministic and reproducible.
